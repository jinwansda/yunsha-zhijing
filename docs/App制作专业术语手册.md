# App制作专业术语手册（对照版）

> 用法：左边是你实际做的事，右边是专业说法，括号里是你项目里对应的东西。
> 记的时候连"对应项目"一起记，评委追问才不会穿帮。

---

## 一、整体架构（怎么定义你这个App）

| 大白话 | 专业说法 | 对应你的项目 |
|---|---|---|
| 一个App里切换页面，不刷新 | 单页应用（SPA，Single Page Application） | index.html 内多视图切换 |
| 界面和后台分开做 | 前后端分离架构 | 前端 JS + 独立 FastAPI 后端 |
| 一套代码能跑网页也能打包安卓 | 跨平台混合应用（Hybrid App） | HBuilderX 5+ App，可打包APK |
| 没网也能用 | 离线优先（Offline First） | 后端不可达自动切本地存储 |
| 基础功能先保证，特效锦上添花 | 渐进增强（Progressive Enhancement） | 特效不支持时功能照常 |
| 出问题能自己往下走、不崩 | 高可用 / 容错设计 | 自动降级、兜底机制 |

## 二、前端技术（界面怎么搭的）

| 大白话 | 专业说法 | 对应你的项目 |
|---|---|---|
| 把功能拆成一块一块写 | 模块化 / 组件化开发 | js/ 下按功能分文件 |
| 数据变了，界面跟着变 | 数据驱动视图渲染 | 状态对象 + 重渲染函数 |
| 点一下触发反应 | 事件驱动编程 | addEventListener 绑定交互 |
| 页面之间跳转 | 客户端路由（hash 路由） | 页内视图切换 |
| 手机电脑都能适配 | 响应式布局（Responsive Layout） | 媒体查询自适应 |
| 图标用代码画的，能放大 | 矢量图形（SVG，可缩放矢量图形） | 47枚3D拟物SVG图标 |
| 用代码实时画图 | Canvas 2D 绘图 | 涂河泥游戏 |
| 网页里做3D立体场景 | WebGL / Three.js 实时渲染 | 3D园区漫游 |
| 数据存在浏览器里 | 客户端持久化存储（localStorage） | 键名 yunsha_v1 |
| 自动检测页面变化并替换 | MutationObserver 增量更新 | 图标自动升级 |
| 操作页面元素 | DOM 操作（文档对象模型） | JS 动态渲染页面 |

## 三、后端与数据（后台怎么搭的）

| 大白话 | 专业说法 | 对应你的项目 |
|---|---|---|
| 后台用Python写的、能同时处理很多请求 | ASGI 异步 Web 框架（FastAPI） | backend/main.py |
| 手机和后台约定好的通信地址 | RESTful API（表述性状态转移接口） | 会话/判题/知识等接口 |
| 一条一直连着的实时通信线 | WebSocket 全双工长连接 | realtime.py，/ws/ue/ |
| 数据存下来 | 数据持久化 | SQLite 数据库 |
| 一个轻量的本地数据库 | 嵌入式关系型数据库（SQLite） | data/yunsha.db |
| 记住你是谁、在哪个会话 | 会话管理（Session） | session_id 机制 |
| 验证身份、防止乱调 | 身份认证 / 接口鉴权 | X-UE-Key |
| 允许跨设备访问的处理 | CORS 跨域资源共享中间件 | 局域网真机联调 |
| 收发的数据格式 | 数据传输对象（DTO） | JSON 请求/响应体 |
| 后台判断对错、不直接给答案 | 服务端判题逻辑 | 判题接口 |

## 四、实时通信（虚实联动那块）

| 大白话 | 专业说法 | 对应你的项目 |
|---|---|---|
| UE和手机能互相随时发消息 | 全双工双向通信 | WebSocket 通道 |
| 按小组分房间，互不干扰 | 基于会话的房间隔离（Room） | /ws/ue/{session_id} |
| UE上报的环境数据 | 遥测数据（Telemetry） | 光照/湿度/气温/风速 |
| 手机发给UE的操作 | 指令下发（Command） | start_drying/set_weather |
| UE办完回话 | 指令回执（ACK） | ack 消息 |
| 定时报活证明在线 | 心跳机制（Heartbeat） | presence 在线状态 |
| 断了自动反复重连 | 指数退避重连（Exponential Backoff） | 重连间隔递增 |
| 长连接坏了用普通请求顶上 | REST 兜底 / 通道降级 | 备用HTTP接口 |
| 新设备进来补发上次数据 | 状态重放（Replay） | 回放最近一帧遥测 |

## 五、AI大模型（问答那块）

| 大白话 | 专业说法 | 对应你的项目 |
|---|---|---|
| 先翻自己资料再让AI回答 | RAG 检索增强生成（Retrieval-Augmented Generation） | rag.py |
| 自己的专业资料库 | 领域知识库 / 语料库 | 18条知识语料 |
| 从资料里找最相关的 | 语义检索 / 相似度匹配（Top-K） | bigram+同义词+加权 |
| 把资料和问题一起发给模型 | 上下文注入（Context） | 检索片段作为上下文 |
| 约束模型怎么回答 | 提示词工程（Prompt Engineering） | 防幻觉 system prompt |
| 模型能记住上文 | 多轮对话 / 指代消解 | history 保留最近6条 |
| 防止AI乱编 | 幻觉抑制（Hallucination Control） | 引用来源、限定材料 |
| 标明答案出自哪 | 引用溯源（Citation） | 答案标注来源 |
| 没网就只用本地资料答 | 服务降级 / 熔断降级 | 自动切本地检索 |
| 让回答更稳定少随机 | 温度参数控制（Temperature=0.3） | 低温度高确定性 |

## 七、一句话把整个项目"专业地"说出来

> "本项目是一个基于混合开发技术栈构建的**跨平台单页应用**，采用**前后端分离架构**：前端以原生技术栈实现模块化、数据驱动的视图层，结合 SVG、Canvas 与 WebGL 完成多模态渲染；后端基于 **ASGI 异步框架**提供 RESTful 接口与 **WebSocket 全双工实时通道**，对接 UE 实现数字孪生遥测与指令联动；AI 层通过 **RAG 检索增强生成**保障领域问答的可溯源性与幻觉抑制，并以**离线优先、优雅降级和多通道兜底**保障系统的高可用性。"

## 八、重要提醒

1. **术语别乱用**，每个词都要能对应到你项目里真实存在的东西
2. 评委如果问"你刚才说的XX是什么意思"，你要能用大白话解释——**所以对照着记，别只记名词**
3. 拿不准的、项目里没有的术语，宁可不说，别硬凹
